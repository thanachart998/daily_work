# โปรแกรมบันทึกงานประจำวันและสรุปผลงานรายเดือน (Worklog Local)

โปรแกรมจัดการงานประจำวัน ติดตามงานค้าง ปฏิทินงาน และออกรายงานสรุปผลงานรายเดือน (พ.ศ. / ค.ศ.) ที่ทำงานในเครื่องของคุณเอง 100% ข้อมูลไม่ถูกส่งออกไปอินเทอร์เน็ต และสามารถใช้งานแบบโปรแกรมทั่วไปด้วยการ **ดับเบิลคลิกเพียงครั้งเดียว**

---

## วิธีใช้สำหรับผู้ใช้ทั่วไป (ดับเบิลคลิกอย่างเดียว ไม่ต้องเปิด Terminal)

คุณ **ไม่ต้องติดตั้งโปรแกรมเสริมใดๆ** และ **ไม่ต้องพิมพ์คำสั่ง** เพียงทำตามขั้นตอนนี้:

### 1. การเปิดใช้งานโปรแกรม
1. เปิดโฟลเดอร์ของโปรแกรม (`Worklog-Portable`)
2. **ดับเบิลคลิกที่ไฟล์ตัวเปิดโปรแกรม** ตามระบบปฏิบัติการของคุณ:
   - **Windows**: ดับเบิลคลิกไฟล์ **`เปิดโปรแกรม.bat`** (หรือดับเบิลคลิกทางลัด **"บันทึกงานประจำวัน"** บนหน้าจอ Desktop)
   - **Mac (macOS)**: ดับเบิลคลิกไฟล์ **`เปิดโปรแกรม.command`**
   - **Linux**: ดับเบิลคลิกไฟล์ **`เปิดโปรแกรม.sh`**
3. รอประมาณ 1–2 วินาที เบราว์เซอร์เริ่มต้นของเครื่อง (เช่น Chrome, Edge, Safari, Firefox) จะเปิดหน้าเว็บโปรแกรมขึ้นมาให้อัตโนมัติโดยไม่มีหน้าต่างคำสั่งสีดำค้างกวนใจ
4. **หากเผลอปิดแท็บเบราว์เซอร์**: ข้อมูลไม่หาย คุณสามารถกลับมา **ดับเบิลคลิกไฟล์ `เปิดโปรแกรม` ซ้ำได้ทันที** โปรแกรมจะเปิดหน้าเว็บกลับขึ้นมาใหม่โดยไม่เปิดเซิร์ฟเวอร์ซ้อน

### 2. การปิดโปรแกรมอย่างปลอดภัย
- **กรณีต้องการพักการใช้งานชั่วคราว**: ปิดแท็บเบราว์เซอร์ได้ตามปกติ (ตัวโปรแกรมเบื้องหลังยังทำงานอยู่เพื่อให้เปิดครั้งถัดไปได้ทันที)
- **กรณีต้องการปิดโปรแกรมทั้งหมด (เช่น ก่อนถอดแฟลชไดรฟ์หรือคัดลอกโฟลเดอร์)**:
  1. กดปุ่ม **"ปิดโปรแกรม"** ที่แถบเมนูด้านซ้ายล่าง (หรือในเมนู **ตั้งค่า**)
  2. กดปุ่มยืนยัน **"ปิดโปรแกรม"**
  3. ระบบจะบันทึกข้อมูลทั้งหมดลงฐานข้อมูลให้เสร็จสมบูรณ์และหยุดการทำงานอย่างปลอดภัย

### 3. การย้ายโฟลเดอร์ไปเครื่องอื่น หรือการอัปเดตโปรแกรมโดยข้อมูลไม่หาย
ภายในโฟลเดอร์โปรแกรมแบ่งโครงสร้างออกเป็นสัดส่วนชัดเจน:
- `เปิดโปรแกรม.bat` / `.command` / `.sh` — ไฟล์สำหรับดับเบิลคลิกเปิดใช้งาน
- `app/` — ตัวโปรแกรมและหน้าเว็บ
- `runtime/` — ตัวรันโปรแกรมในตัว (ทำให้เปิดในเครื่องที่ไม่เคยลง Node.js ได้ทันที)
- `data/` — **โฟลเดอร์เก็บฐานข้อมูลของคุณ (`data/worklog.db`)**
- `logs/` — โฟลเดอร์เก็บประวัติการทำงานและสาเหตุกรณีเกิดข้อผิดพลาด (`logs/app.log`)

> **การย้ายเครื่อง**: คัดลอกทั้งโฟลเดอร์ไปวางที่ใดก็ได้ หรือใส่แฟลชไดรฟ์ไปเปิดเครื่องอื่น ข้อมูลในโฟลเดอร์ `data/` จะตามไปด้วยทั้งหมด
>
> **การอัปเดตโปรแกรมเวอร์ชันใหม่**: นำเฉพาะโฟลเดอร์ `app/` ของเวอร์ชันใหม่มาวางทับของเดิม **โดยไม่ต้องลบโฟลเดอร์ `data/`** ข้อมูลงานทั้งหมดจะยังคงอยู่ครบถ้วน

### 4. ฟีเจอร์เสริมเพื่อความสะดวก (ไม่บังคับ)
- **สร้างไอคอนบนหน้าจอ Desktop (Windows)**: ดับเบิลคลิกไฟล์ **`สร้างทางลัดบนหน้าจอ.bat`** จะได้ไอคอน **"บันทึกงานประจำวัน"** บนหน้าจอ Desktop ทันที
- **เปิดโปรแกรมอัตโนมัติเมื่อเปิดเครื่อง (Windows)**: ดับเบิลคลิกไฟล์ **`ตั้งค่าเปิดอัตโนมัติ.bat`** เพื่อเปิดใช้งาน (และหากต้องการยกเลิก ให้ดับเบิลคลิกไฟล์เดิมซ้ำอีกครั้ง)
- **ติดตั้งเป็นแอปหน้าต่างแยก (PWA บน Chrome / Edge)**: เมื่อหน้าเว็บเปิดขึ้นมา สามารถกดไอคอน **"ติดตั้งแอป" (Install App)** ที่แถบที่อยู่ด้านบนของ Chrome หรือ Microsoft Edge เพื่อเปิดใช้งานเป็นหน้าต่างโปรแกรมแยกต่างหากได้

## การบริหารจัดการ "โปรเจกต์ระยะยาวหลายเดือน" (Projects & Milestones)

นอกจากงานประจำวันแล้ว โปรแกรมรองรับการติดตามโปรเจกต์ที่ใช้เวลาต่อเนื่องหลายเดือนและออกรายงานความคืบหน้ารายเดือนได้แม้โปรเจกต์ยังไม่จบ:

1. **สร้างโปรเจกต์ระยะยาวและแบ่งระยะ (Milestone)**:
   - ไปที่เมนู **"โปรเจกต์"** กด **"สร้างโปรเจกต์ใหม่"** กำหนดช่วงเวลาเริ่มต้น–วันสิ้นสุดตามแผน สีประจำโปรเจกต์ และวิธีคำนวณความคืบหน้า (`คำนวณอัตโนมัติจากงานย่อย` หรือ `กำหนดเปอร์เซ็นต์เอง`)
   - คลิกเข้าไปในหน้ารายละเอียดโปรเจกต์ เพื่อเพิ่ม **Milestone ย่อย** (เช่น เฟส 1, เฟส 2, เฟส 3) พร้อมวันครบกำหนดของแต่ละระยะ
   - สามารถกดปุ่ม **"คัดลอกแม่แบบ"** เพื่อนำโครงสร้างโปรเจกต์และรายการ Milestone ไปใช้สร้างโปรเจกต์ใหม่ที่มีรูปแบบคล้ายกันได้ทันที
2. **ผูกงานรายวันเข้ากับโปรเจกต์และงานหลายวัน (Multi-day Tasks)**:
   - ในหน้าเพิ่ม/แก้ไขงาน สามารถเลือก **โปรเจกต์** และ **Milestone ย่อย** ที่งานนั้นสังกัดอยู่ได้ (หรือไม่เลือกเพื่อบันทึกเป็นงานทั่วไปตามปกติ)
   - รองรับการกำหนด **"ทำถึงวันที่ (งานหลายวัน)"** สำหรับงานที่ทำต่อเนื่องหลายวันเพื่อให้แสดงในปฏิทินครบทุกวันในช่วงเวลาดังกล่าว
   - เมื่อทำงานย่อยใน Milestone เสร็จครบทุกงาน ระบบจะแสดงหน้าต่างถามยืนยันว่าต้องการเปลี่ยนสถานะ Milestone นั้นเป็น "เสร็จแล้ว" ด้วยหรือไม่
3. **สรุปความคืบหน้าโปรเจกต์ในรายงานรายเดือน**:
   - ในหน้า **"รายงาน"** จะแสดงหมวด **"ความคืบหน้าโปรเจกต์ระยะยาว"** แยกจาก **"งานทั่วไป"** อย่างชัดเจน
   - แสดง % ความคืบหน้าสะสม ณ สิ้นเดือน และ % ที่เพิ่มขึ้นจากเดือนก่อนหน้า พร้อมรายการงานย่อยและ Milestone ที่ทำเสร็จจริงในเดือนนั้น (ไม่นับงานซ้ำข้ามเดือน และไม่นับงานที่ยังไม่เสร็จเป็นผลงาน)
   - สามารถกดปุ่ม **"เขียนอัปเดตเดือนนี้ / แก้ไขอัปเดตเดือนนี้"** จากหน้ารายงานเพื่อบันทึกสิ่งที่ทำในเดือนนั้น ปัญหา/อุปสรรค และแผนงานเดือนถัดไป ซึ่งจะถูกรวมอยู่ในข้อความสรุปสำหรับคัดลอก การพิมพ์/PDF และการส่งออกไฟล์ CSV (Excel)
4. **มุมมองเส้นเวลา (Timeline) และการแจ้งเตือนโปรเจกต์นิ่ง**:
   - เมนู **"เส้นเวลา"** แสดงแถบช่วงเวลาของทุกโปรเจกต์และ Milestone ข้ามเดือน พร้อมเส้นบอกตำแหน่ง **"วันนี้"** และปุ่มสลับมุมมองรายเดือน (3 เดือน) / รายไตรมาส (6 เดือน)
   - หน้า **"ภาพรวม"** จะแจ้งเตือนอัตโนมัติเมื่อมีโปรเจกต์ใกล้ครบกำหนด หรือไม่มีความเคลื่อนไหวเกิน 14 วัน (**"โปรเจกต์นิ่ง"**)
5. **การอัปเกรดฐานข้อมูลและสำรองข้อมูลอย่างปลอดภัย**:
   - ทุกครั้งที่โปรแกรมอัปเกรดโครงสร้างฐานข้อมูล (`PRAGMA user_version`) ระบบจะสำรองไฟล์ `data/worklog.db` เป็น `data/worklog.db.bak` ให้อัตโนมัติก่อนเสมอ และทำงานภายใต้ Transaction ที่ย้อนกลับได้ทันทีหากเกิดข้อผิดพลาด
   - ระบบ **สำรองและกู้คืนข้อมูล (.json)** รองรับทั้งข้อมูลโปรเจกต์ Milestone บันทึกความคืบหน้ารายเดือน และยังสามารถนำเข้าไฟล์สำรองข้อมูลรุ่นเก่าได้ตามปกติ

## การแก้ไขปัญหาเบื้องต้น
- หากดับเบิลคลิกแล้วโปรแกรมไม่สามารถเริ่มทำงานได้ ระบบจะแสดงหน้าต่างแจ้งสาเหตุเป็นภาษาไทย และบันทึกรายละเอียดไว้ที่ไฟล์ **`logs/app.log`**
- หากพอร์ตหลัก (`3000`) มีโปรแกรมอื่นในเครื่องใช้งานอยู่ ระบบจะเลือกพอร์ตถัดไปที่ว่าง (เช่น `3001`, `3002`) และเปิดเบราว์เซอร์ไปยังพอร์ตนั้นให้อัตโนมัติ

## สำหรับผู้พัฒนา: การสร้างแพ็กเกจแบบพกพา (`npm run package`)

หากต้องการแก้ไขโค้ดและสร้างโฟลเดอร์แบบพกพา (`release/Worklog-Portable`) ที่รวม Node.js runtime พร้อมส่งมอบให้ผู้ใช้ปลายทาง:

```bash
npm install
npm run package
```

คำสั่ง `npm run package` จะทำขั้นตอนต่อไปนี้อัตโนมัติ:
1. Build หน้าเว็บ React + Tailwind + ฟอนต์ภาษาไทย Sarabun (แบบออฟไลน์ในตัว) และไฟล์ PWA (`manifest.webmanifest`, `sw.js`)
2. Bundle โค้ดฝั่ง Server ทั้งหมด (`server/index.ts` และไลบรารี) ให้เป็นไฟล์เดียวที่ `app/server.cjs`
3. คัดลอก Node.js runtime ของระบบใส่ลงใน `release/Worklog-Portable/runtime/`
4. จัดเตรียมตัวเปิดโปรแกรม (`เปิดโปรแกรม.bat`, `เปิดโปรแกรม.command`, `เปิดโปรแกรม.sh`) พร้อมโฟลเดอร์ `data/` และ `logs/` ที่แยกออกจาก `app/`

### เหตุผลที่เลือกใช้ `node:sqlite` แทน `better-sqlite3` สำหรับการแพ็กแบบพกพา
- `better-sqlite3` เป็น Native C++ Addon (`.node` binary) ที่ผูกติดกับสถาปัตยกรรม CPU, ระบบปฏิบัติการ และเลขเวอร์ชัน ABI ของ Node.js อย่างเคร่งครัด ทำให้เวลาแพ็กเป็นโฟลเดอร์พกพาหรือย้ายเครื่องมักเกิดปัญหาโหลดไฟล์ `.node` ไม่ได้ ต้องพึ่งพา C++ Build Tools (`node-gyp`) หรือถูกบล็อกจากนโยบายความปลอดภัยของบางเครื่อง
- **`node:sqlite` (`DatabaseSync`)** เป็นโมดูลฐานข้อมูล SQLite ที่ฝังมาในตัวไบนารีของ Node.js (ตั้งแต่ Node.js 22.5 ขึ้นไป) โดยตรง ทำให้เมื่อคัดลอก `node.exe` ไปไว้ในโฟลเดอร์ `runtime/` ตัวโปรแกรมสามารถใช้งานฐานข้อมูล SQLite โหมด WAL และ Transaction ได้ทันทีโดย **ไม่ต้องมีไฟล์ `.node` แยกภายนอก และไม่ต้องพึ่งพา `node_modules`** ส่งผลให้โฟลเดอร์พกพามีขนาดกะทัดรัด เสถียร และย้ายไปเปิดบนเครื่องที่ไม่เคยติดตั้ง Node.js ได้ 100%
